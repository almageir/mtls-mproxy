# mtls-mproxy

**mtls-mproxy** это кроссплатформенный многоцелевой прокси сервер, разработкой которого я занимаюсь в свое свободное
время в учебно-исследовательских целях и в качестве хобби. 
Проект пишу на С++. В нем используются:

- [CMake](https://cmake.org) в качестве системы управления сборкой проекта
- [C++ asio](https://github.com/chriskohlhoff/asio) для асинхронных операций ввода/вывода
- [OpenSSL](https://openssl-library.org) для криптографических операций

Предполагается его использование в паре с другим моим проектом [mtls-tun](https://github.com/almageir/mtls-tun).
В принципе, mtls-mproxy будет работать с любой программой, которая реализует функционал прозрачного TLS туннеля до
машины, на которой выполняется mtls-mproxy, при условии, что обе программы успешно проверят сертификаты друг друга.

Под прозрачностью туннеля я понимаю, что данные по нему передаются `as is` в зашифрованном виде и без использования
мультиплексирования. То есть, если браузер с включенным Socks5 прокси устанавливает 3 соединения с mtls-tun, 
то mtls-tun, в свою очередь, создаст 3 независимых TLS соединения с mlts-proxy, а не одно, через которое пойдет трафик 
от 3 входящих соединений.

![Архитектура mtls-mproxy(mtls-tun)](https://github.com/almageir/mtls-mproxy/blob/master/doc/mtls-mrpxy-arch.png)

## Функционал

На текущий момент реализованы 3 основных режима работы:

- SOCKS 5 прокси
  - TCP CONNECT
  - UDP ASSOCIATE
  - ~~TCP BIND~~
- HTTP/HTTPS прокси
- TCP port forwarding
- mTLS (Mutual TLS) authentication

## Особенности

Сам по себе mtls-mproxy представляет собой обычный прокси сервер. Но при использовании в паре с mtls-tun 
применяется взаимная аутентификация mTLS на базе классического PKI.

Для аутентификации необходимы:
- сертификат и приватный ключ на стороне клиента (mtls-tun)
- сертификат и приватный ключ на стороне сервера (mtls-mproxy)
- серверный и клиентский сертификаты должны быть подписаны центром сертификации (CA)

Установление зашифрованного TLS соединения между mtls-tun и mtls-mproxy возможно только после взаимной 
проверки сертификатов между сервером и клиентом.
